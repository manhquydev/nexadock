# Option A — Win32 Native Window Hosting (`SetParent`) Empirical Feasibility Report

- **Spike Directory**: `desktop-instance-manager/spikes/native-hosting/` (standalone Cargo `[workspace]`, zero external dependencies, removable)
- **Test Environment**: Windows (Session 1, System DPI `120` = 125% scaling, Integrity `Medium(0x2000)`, Keyboard Layout `HKL 0x0409`)
- **Safety Compliance**: Zero mutating Win32 calls on any live `Zalo.exe`, `ZaloCall.exe`, or `ZaloCap.exe` process/HWND; zero access to `%LOCALAPPDATA%\ZaloPC` or `%APPDATA%\ZaloData`. All live Zalo counts remained identical (`17 Zalo.exe`, `2 ZaloCall.exe`, `2 ZaloCap.exe`).
- **Verdict**: **BLOCKED for production** (not even safe as a default experimental flag for Primary or daily-driver Zalo accounts). Cross-process Win32 `SetParent` fails **6 independent production kill-criteria** empirically on Chromium/Electron-architecture (`Chrome_WidgetWin_1` + GPU `Intermediate D3D Window`) and Win32 native fixtures.
