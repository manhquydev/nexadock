**Quy ước nhãn bằng chứng bắt buộc:**

## 3. Nhận Định Kiến Trúc Xuyên Nền Tảng (Cross-Platform Synthesis)

1. **Sự tương đồng gốc rễ trong `app.asar`:** Trên cả ba nền tảng (kể cả bản cộng đồng Linux vốn trích xuất từ macOS `app.asar`), Zalo Desktop đều có chung kiến trúc lưu trữ đơn thư mục `ZaloData` đặt trước `requestSingleInstanceLock()`. Nhờ đó, **mô hình cô lập biến môi trường cấp tiến trình mà không chỉnh sửa `app.asar`** giải quyết trọn vẹn bài toán tách dữ liệu, đăng nhập độc lập và giữ phiên qua khởi động lại trên Windows và macOS.
2. **Sự phân kỳ lớn nhất nằm ở kênh IPC phụ trợ của Cuộc gọi (`call-v2`):**
   - Windows dùng Named Pipe toàn cục **không tự gỡ** (`PipeZCall*` -> phiên đầu thắng, phiên sau lỗi và làm nhiễu phiên đầu).
   - macOS dùng Unix socket `/tmp` **có `fs.unlink` cưỡng bức** (`/tmp/socketzalo*2021` -> phiên mở cuối thắng).
   - Bản cộng đồng Linux đổi sang **TCP loopback cổng cứng** (`127.0.0.1:29631/29632` -> phiên đầu thắng, trừ khi tách network namespace).
3. **Tỷ trọng lỗi có thể sửa ngay trong mã của chính dự án (`desktop-instance-manager`):** Hơn **60% rào cản UX ngoài cuộc gọi** (hộp thoại tệp rỗng trên Windows/Linux, bắt nhầm cửa sổ `notiWin` trên Windows, lỗi `TMPDIR` > 104 byte & `SIGTERM` sớm trên macOS, lỗi `--die-with-parent` & thiếu socket trên Linux `bwrap`, thiếu chốt chặn `db_path` ngoài khi backup) **thuộc về thiết kế Adapter hiện tại và hoàn toàn có thể sửa sạch bằng mã hợp chuẩn an toàn**.
