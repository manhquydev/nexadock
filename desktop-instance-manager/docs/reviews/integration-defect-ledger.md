### 1.2 Allowed `Current status` State Machine & Epistemic Discipline

Every row in Section 2 strictly uses **exactly one** of the seven canonical status tokens:

1. **`OPEN`:** Defect or backlog gap confirmed in source/design (`Confirmed by source code` / `STATIC_CONFIRMED`) with no complete candidate remediation committed yet (or a partial branch fix that leaves a mandatory acceptance criterion open).
2. **`REPRODUCED`:** Defect dynamically triggered at runtime on a host OS (`RUNTIME_REPRODUCED`) with no verified remediation committed on the target track.
3. **`FIXED_CANDIDATE`:** Code remediation is committed on an unverified or unmerged branch (specifically Agent A's `feat/macos-multi-instance` @ `8628224` or Agent B's `feat/ubuntu-multi-instance` @ `62dc5d1`, tagged **`ALREADY_FIXED_CANDIDATE`** in `Verification evidence`), OR awaits execution on a native target-OS kernel (`macOS 14+` / `Ubuntu 24.04`). **`FIXED_CANDIDATE` is NEVER conflated with `VERIFIED`.**
4. **`VERIFIED`:** Code remediation is committed in `<INTEGRATION_CODE_SHA>` (`58dbd61b9454bab96493819bc1517032bbf5b968`) AND independently verified at runtime on the target host OS by `c2-verifier` (`--mode release-regression` exit `0`), with zero bystander profile mutation, adjacent suites passing (`0` `FAIL_UNEXPECTED`), soak cycles green (`REL-01` `10/10`, `REL-02` `100/100`), parallel suite stress passing (`7/7`), and `100%` primary Zalo Desktop invariance. *(Where a portable Shared Core fix also governs POSIX runtime behavior, Windows/Core execution is `VERIFIED` while native POSIX kernel verification is explicitly noted in `Remaining blocker`.)*
5. **`BLOCKED`:** Architectural vendor design, OS security policy, or hardware single-opener constraint that cannot be bypassed without violating non-negotiable safety invariants (zero binary/ASAR patching, zero `Zalo.lnk` tampering, zero `--no-sandbox` / SAC / AppArmor bypass, zero fake `codesign` re-signing).
6. **`NOT_TESTED`:** Hypothesis (`Inference` / `Author claim`) or human-only opt-in protocol (`TC-H1B` L3 live QR login & Stage 2 call check, `TC-H2` Part 2B, `TC-H4` Part 4D, `L5` live upgrade soak) not yet executed on target hardware or with consenting human tester accounts.
7. **`FALSE_POSITIVE`:** Previously suspected issue proven non-existent by controlled experiment without requiring code changes (`0` items currently use this status; downgraded Mission D over-claims were recalibrated to `Inference` + `NOT_TESTED` rather than dismissed without runtime proof).
